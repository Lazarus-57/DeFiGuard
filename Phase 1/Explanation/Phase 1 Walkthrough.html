SHAP Explainability & Automatic Pattern Classification

We generated SHAP (SHapley Additive exPlanations) values for every transaction in the test set. These values break down exactly why a transaction was flagged — not just that it was flagged.

We also implemented an automatic Pattern Classification system baked directly into the backend, using SHAP contributions as the signal:

🕸️
Smurfing (Structural)
Flagged when the top SHAP reasons start with gnn_ — meaning the wallet's structural position in the transaction network is anomalous (fan-out/fan-in topology detected by GraphSAGE).
⏱️
Peel / Circular (Temporal)
Flagged when the top SHAP reasons end with _nts — meaning the wallet's temporal spread pattern is anomalous (funds moving too fast or too uniformly in time).

This fulfills Requirements #2 and #3 of the frontend design without needing to train a secondary classification model.

The Backend API — inference.py

All of the complexity — GNN loading, NTS lookups, SHAP computation — is hidden behind a single clean Python class. Your teammates do not need to understand any of the machine learning to use it.

Phase 1/scripts/inference.py — Usage Example 
import pandas as pd
from inference import DefiGuardInference

# 1. Load once at application startup
ml_engine = DefiGuardInference()

# 2. Get raw transactions from the frontend / database
raw_df = pd.read_csv("user_uploaded_transactions.csv")

# 3. Run the magic — one line
results = ml_engine.predict(raw_df)

The results DataFrame is your original data with four new columns automatically attached:

suspicion_score
float (0.0 → 1.0)
How confident the model is that this transaction is money laundering. Use this for risk ranking.
aml_flag
int (0 or 1)
Binary decision. 1 = suspicious, 0 = clean, based on the optimal threshold (0.448).
pattern_type
string
"Smurfing (Structural)", "Peel/Circular (Temporal)", or "Normal". Auto-classified by SHAP.
top_shap_reason
string
The single highest-contributing feature that caused the alert. Use this in explainability charts.

The 25k Capability Stress Test

We ran the completed backend on the legacy 25k dataset to test how it behaves on out-of-distribution, messy, real-world-style data it had never seen before.

1,626
transactions flagged as suspicious out of 26,854 total (6.05%)
🔬 Fascinating Finding

Every single one of the 1,626 flagged transactions was classified as "Peel/Circular (Temporal)", with to_nts as the top SHAP reason.

This means the model instantly detected the temporal data leakage bug present in the 25k dataset (the randomised timestamps from the old pipeline). The model's temporal intelligence identified that the synthetic transaction timing was unnatural — exactly what it was designed to do. This perfectly validates our decision to abandon the 25k dataset for training.

Step-by-step integration guide:

1
Set up your backend server (FastAPI / Flask)
Create a Python API server. Import DefiGuardInference from Phase 1/scripts/inference.py and initialize it once at startup — it loads all the model artifacts automatically from the Phase 1 Models/ folder.
2
Create a file-upload endpoint
Accept a CSV upload from the frontend. Read it into a Pandas DataFrame using pd.read_csv(). No special preprocessing needed — the engine handles everything.
3
Call ml_engine.predict(df)
Pass the raw DataFrame to the predict function. It returns the same DataFrame with the four output columns attached: suspicion_score, aml_flag, pattern_type, and top_shap_reason.
4
Return the results to the frontend as JSON
Convert the results DataFrame to JSON and send it back. The frontend can then render the flagged transactions in a table, display a graph visualization of the pattern, and show the SHAP reason as the "explanation" for investigators.
